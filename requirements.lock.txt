# AI 小工具 —— 依赖锁文件（交付源码时用它，别用 requirements.txt）
#
# ★ 为什么必须钉死版本：
#   原来的 requirements.txt 只写 `>=`，客户 pip install 会装到「当时最新」的版本。
#   而 cloakbrowser 是 stealth Chromium 的封装 —— 它换个版本，浏览器指纹行为就可能变，
#   表现成「注册成功率莫名下降」，而且极难归因（实测：装的是 0.5.11，已有 0.5.12）。
#
# ★ 这个文件是怎么生成的（别再用 pip freeze 本机 venv 了）：
#   第一版是拿开发机 venv 全量 freeze 减几个打包包 —— 结果把 paramiko / scipy / tqdm
#   这些**跟本工具无关**的包也锁了进去，客户白下几十 MB，还引发过一次依赖冲突。
#   正确做法：建一个**干净 venv**，只按 requirements.txt 装，再 freeze。
#       python -m venv %TEMP%\lockvenv
#       %TEMP%\lockvenv\Scripts\python.exe -m pip install -r requirements.txt
#       %TEMP%\lockvenv\Scripts\python.exe -m pip freeze > requirements.lock.txt
#
# ★ 但「干净 venv 装出来」= 锁那一刻的最新版，**不等于我们验证过的版本**。
#   所以 cloakbrowser 被手工钉回 0.5.11 —— 注册 / 2FA / 激活 / 交付这一整套
#   端到端验证都是在 0.5.11 上跑的（0.5.12 已发布但我们没实测过）。
#   两个版本期望的内核版本相同（146.0.7680.177.5，已核对），所以换版本不影响
#   内置内核的识别；但封装层的差异没人测过，就不冒这个险。
#   要升级它 = 一次**有意识的、可回归的**变更，不是 pip 顺手带上来的。
#
